# PixelVault

An offline-first ROM catalogue and downloader for Android. You point it at
sources you already have access to (HTTP directory listings or magnet links),
it indexes what is there — names, regions, languages, formats, sizes — and
downloads to a folder you choose, with resumable transfers and background
progress.

PixelVault ships with **no sources configured**. `assets/consoles.json` seeds
an empty console/manufacturer catalogue; every source is added by the user,
either by hand or through an install link from the companion site.

## Stack

Flutter (Android only) · Riverpod · Drift/SQLite · go_router · dio.
Torrent support and 7-Zip extraction live in the bundled
`plugins/pixelvault_torrent` plugin (libtorrent4j + 7-Zip-JBinding behind a
method/event channel).

```
lib/
  core/        db · download · scraping · security · settings · state · theme
  features/    one directory per screen
  l10n/        ARB files — pt (template), en, es, fr, de
plugins/pixelvault_torrent/   native Android torrent + extraction plugin
```

## Getting started

```bash
flutter pub get
dart run build_runner build      # Drift + Riverpod + JSON codegen
flutter run
```

Codegen is required after touching anything with a `part '*.g.dart'`
directive — the Drift tables, the Riverpod providers, the JSON models.

Translations regenerate with `flutter gen-l10n` after editing `lib/l10n/*.arb`.
All five locales must stay at the same key count; `pt` is the template.

## Tests

```bash
flutter analyze                              # must be clean
flutter test                                 # unit + widget
flutter test integration_test/               # needs a device/emulator
cd android && ./gradlew :pixelvault_torrent:testDebugUnitTest   # Kotlin
```

The Gradle wrapper is generated by the Flutter tool on the first Android
build, so run `flutter build apk --debug` once before the Kotlin tests.

## Deep-link HMAC secret

`lib/core/deeplink/source_install_client.dart` HMAC-signs every request that
resolves a `pixelvault://install?token=...` deep link against the companion
website's `/api/resolve` endpoint. The shared secret is passed in at build
time via `--dart-define=PIXELVAULT_HMAC_SECRET=<value>` (or, more
conveniently, `--dart-define-from-file`) — it is never committed to the repo.

- **Default** (`flutter run`, `flutter build apk --debug`/`--profile`): no
  setup needed. A placeholder secret is used automatically, the app opens
  normally, and any real "Instalar" tap fails with a translated "this link is
  no longer valid" message (the server rejects the placeholder) rather than
  crashing.
- **To resolve real deep links locally**: copy `secrets.example.json` to
  `secrets.json` (git-ignored), fill in the real value (the same one
  configured as the `PIXELVAULT_HMAC_SECRET` env var on the companion site's
  Vercel deployment), and run with
  `flutter run --dart-define-from-file=secrets.json`.
- **Release builds** (`flutter build apk --release`/`appbundle`) **must**
  pass the real secret via `--dart-define-from-file=secrets.json` (or CI
  secret injection) — omitting it throws a clear `StateError` at startup
  instead of silently shipping a broken or insecure build.

The secret is a deterrent, not real security: it is extractable from the APK.
It raises the bar from "copy one header string" to "reverse-engineer the
compiled app".

## Release signing

`flutter build apk --release` uses `android/key.properties` (git-ignored) when
present and falls back to the debug key otherwise, so a fresh checkout still
builds. Only a genuinely distributable build needs the real keystore.

Release APKs drop the `x86_64` ABI (emulator/ChromeOS only), which removes
roughly 40 MB of libtorrent native code. `flutter run --release` therefore
will not work on an x86_64 emulator; debug builds keep every ABI.

## Notes on data

- Console source URLs are encrypted at rest (AES-256-GCM, key in the Android
  Keystore) so a raw database pull does not reveal them.
- The download queue and history live in their own table, deliberately with
  no foreign key onto the catalogue: a rescan wipes and repopulates catalogue
  rows, and the user's history must survive that.
- Fonts are bundled assets, not fetched at runtime, so a first launch with no
  network still renders correctly.
